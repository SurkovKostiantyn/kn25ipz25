## 🧠 Максимально просте пояснення всіх тем (як для дітей)

### 1. Чим відрізняються GET і POST?
* **GET** — це як **відкрита листівка**. Коли ви відкриваєте сторінку або шукаєте щось у Google, параметри записуються прямо в адресу сайту (наприклад, `index.php?created=1`). Їх бачить кожен у рядку браузера. Метод GET використовують для **перегляду** даних.
* **POST** — це як **запечатаний конверт**. Коли користувач вводить пароль або відправляє великий текст через форму, дані ховаються всередині тіла запиту і не показуються в адресному рядку браузера. Метод POST використовують для **збереження або зміни** даних.

---

### 2. Як форма надсилає дані у PHP?
У HTML кожен елемент форми має важливий атрибут `name`:
```html
<input type="text" name="title">
```
Коли користувач тисне кнопку «Зберегти», браузер формує суперглобальний масив `$_POST`, де ключами стають саме значення атрибута `name`:
```php
$_POST['title']; // Тут буде те, що користувач надрукував у полі "title"
```

---

### 3. Навіщо потрібен `var_dump()`? (Лаба №6)
`var_dump()` — це як «рентген» для змінних. Вона показує:
1. Який тип має змінна (рядок `string`, масив `array`, число `int`).
2. Скільки символів або елементів у ній є.
3. Що саме там записано.

У нашому коді `create.php`, якщо виникають помилки, ми виводимо блок налагодження:
```php
echo "<pre>";
var_dump($_POST);
echo "</pre>";
```
Це допомагає програмісту своїми очима побачити, що саме прийшло від браузера.

---

### 4. Санація даних: `trim()` та `htmlspecialchars()` (Лаба №7)
Користувачі можуть випадково чи навмисно ввести некоректні дані:
1. **`trim($string)`** — видаляє зайві пробіли на початку та в кінці тексту. Якщо користувач ввів `"   Купити молоко   "`, функція перетворить це на чисте `"Купити молоко"`.
2. **`htmlspecialchars($string)`** — наш надійний щит від зловмисників (**захист від XSS**). Якщо хуліган введе у форму вірусний код:
   ```html
   <script>alert('Вас зламано!');</script>
   ```
   Функція `htmlspecialchars` перетворить небезпечні значки `<` та `>` на нешкідливі текстові сутності `&lt;` та `&gt;`. Браузер надрукує цей напис як звичайний текст і НЕ буде запускати шкідливу програму.

---

### 5. Валідація: як ми перевіряємо поля? (Лаба №7)
Перед збереженням ми обов'язково перевіряємо, чи користувач не відправив порожні поля:
```php
$errors = []; // Наша скринька для запису помилок

if (empty($title)) {
    $errors[] = "Поле «Назва завдання» є обов'язковим для заповнення!";
}

if (empty($description)) {
    $errors[] = "Поле «Опис завдання» є обов'язковим для заповнення!";
}
```
Якщо в масиві `$errors` є хоча б одна помилка (`!empty($errors)`), ми показуємо користувачеві червоний блок сповіщення прямо над формою.

### 6. Що таке «Sticky Forms» («липка форма»)? (Завдання з зірочкою)
Уявіть ситуацію: ви старанно писали довгий опис на 10 речень, але забули вказати пріоритет. Ви тиснете «Зберегти», сторінка перезавантажується — і все, що ви писали, зникає! Це дуже дратує.

**Липка форма** запам'ятовує те, що ви вже ввели, і підставляє значення назад:
- Для `<input>`: `value="<?= $title ?>"`
- Для `<textarea>`: `<textarea><?= $description ?></textarea>`
- Для `<select>`: якщо було обрано `High`, ми додаємо атрибут `selected`.

Користувачу не доведеться нічого набирати заново!

---

### 7. Як зберігаються дані у `data.json`?
1. Перевіряємо `file_exists('data.json')` — щоб не викликати помилку, якщо файлу ще немає.
2. Зчитуємо вміст за допомогою `file_get_contents()`.
3. Перетворюємо JSON у звичайний PHP-масив через `json_decode(..., true)`.
4. Додаємо нове завдання: `$tasks[] = [...]`.
5. Перетворюємо масив назад у JSON через `json_encode($tasks, JSON_UNESCAPED_UNICODE | JSON_PRETTY_PRINT)`.
6. Записуємо у файл через `file_put_contents('data.json', $json_data, LOCK_EX)`. Параметр `LOCK_EX` тимчасово замикає файл, щоб два користувачі не зіпсували дані при одночасному збереженні.
7. Перенаправляємо на `index.php?created=1` через заголовок `header('Location: ...')`.
