# Лабораторна робота 10: Основи ООП в PHP (Менеджер завдань)

Цей проєкт демонструє практичне застосування об'єктно-орієнтованого програмування (ООП) у PHP на прикладі вебдодатку «Менеджер завдань» (Task Manager) із авторизацією користувача та збереженням даних у JSON-файл.

---

## Основні концепції ООП у проєкті

Ключові принципи та можливості мови, використані в коді:
- класи та об'єкти - розділення відповідальності між моделлю даних `Task` та репозиторієм `TaskRepository`;
- інкапсуляція - приховування внутрішнього стану властивостей за допомогою `private` та надання доступу через публічні методи-геттери;
- властивості лише для читання (`readonly`) - гарантія незмінності ідентифікатора `id` після ініціалізації об'єкта;
- спрощений синтаксис конструктора - використання Constructor Property Promotion у PHP 8 для компактного оголошення та ініціалізації полів;
- валідація та винятки - перевірка коректності переданих параметрів у конструкторі та викидання `InvalidArgumentException`;
- інкапсуляція бізнес-логіки - перенесення логіки перевірки дедлайну (`isOverdue`), завершення (`complete`) та отримання мітки статусу всередину класу сутності;
- патерн Repository - відокремлення логіки збереження, читання та фільтрації даних від представлення;
- статичні фабричні методи - метод `Task::fromArray()` для створення екземплярів об'єктів зі збережених у JSON даних.

## Опис файлів

Призначення кожного файлу в проєкті:
- `Task.php` - клас моделі завдання, що інкапсулює поля `id`, `title`, `isCompleted`, `deadline`, а також методи для зміни стану та серіалізації;
- `TaskRepository.php` - клас управління сутностями завдань, що відповідає за додавання, пошук, відмітку виконання, видалення та підрахунок статистики;
- `index.php` - інтерфейс користувача для перегляду статистики, додавання нових задач і зміни статусів через виклики методів репозиторію;
- `login.php` - сторінка автентифікації користувача та ініціалізації сесії;
- `tasks.json` - файл для персистентного зберігання масиву завдань у форматі JSON;
- `readme.md` - документація проєкту з описом реалізації та теоретичних аспектів ООП.

## Реалізація ООП у коді

### Клас сутності `Task` (`Task.php`)
Клас моделює сутність завдання та інкапсулює його поведінку:
- просування властивостей конструктора - поля описуються безпосередньо в аргументах `__construct()`;
- валідація при створенні - заборона створення завдання з порожнім заголовком:
  ```php
  if (empty(trim($title))) {
      throw new InvalidArgumentException('Назва завдання не може бути порожньою.');
  }
  ```
- бізнес-методи - метод `isOverdue()` порівнює дату дедлайну з поточним часом через `strtotime()`, а `getStatusLabel()` повертає рядок статусу;
- серіалізація та десеріалізація - метод `toArray()` конвертує об'єкт у масив для збереження, а фабричний метод `fromArray()` відновлює об'єкт.

---

### Клас сховища `TaskRepository` (`TaskRepository.php`)
Клас інкапсулює операції читання та запису даних у файл:
- завантаження об'єктів - метод `load()` зчитує `tasks.json` і створює масив екземплярів `Task`:
  ```php
  $this->tasks = array_map(fn(array $item) => Task::fromArray($item), $data);
  ```
- персистентність - метод `save()` перетворює колекцію об'єктів у масиви та зберігає у JSON:
  ```php
  $data = array_map(fn(Task $t) => $t->toArray(), $this->tasks);
  file_put_contents($this->storageFile, json_encode($data, JSON_PRETTY_PRINT | JSON_UNESCAPED_UNICODE));
  ```
- агрегація та фільтрація - використання стрілкових функцій з `array_filter` для підрахунку виконаних і прострочених завдань;
- автоінкремент ідентифікаторів - генерація наступного `id` на основі максимального існуючого значення.

---

### Інтеграція в інтерфейс (`index.php`)
Контролер взаємодіє з даними виключно через об'єкт репозиторію:
- ініціалізація репозиторію - створення екземпляра `$repo = new TaskRepository(__DIR__ . '/tasks.json')`;
- обробка запитів - виклики `$repo->add()`, `$repo->complete()` та `$repo->delete()`;
- виведення даних - отримання списку об'єктів через `$repo->findAll()` та звернення до властивостей через геттери.
