# Лабораторна робота 11: Робота з асинхронним JavaScript та станами завантаження

## Опис роботи
У цій лабораторній роботі реалізовано роботу з асинхронним кодом у JavaScript. Ми створили імітацію отримання товарів із сервера: додали штучну затримку, створили індикатор завантаження (спінер), налаштували перемикання станів інтерфейсу та обробку помилок.

---

## Що було зроблено

### 1. Створення затримки на базі Promise
У реальних вебдодатках дані з сервера не надходять миттєво. Щоб змоделювати таку поведінку, використовується затримка на базі об'єкта Promise та таймера setTimeout. Це дозволяє призупинити виконання коду на задану кількість мілісекунд і повертає проміс, який завершується успіхом після закінчення часу.

### 2. Огортання масиву товарів у функцію fetchProducts()
Синхронний масив товарів `products` було огорнуто в асинхронну функцію `fetchProducts()`, яка повертає Promise. Завдяки цьому отримання списку товарів відбувається через штучну затримку (2.5 секунди), точно так само, як це відбувається під час реального мережевого запиту до сервера чи бази даних.

### 3. Додавання компонента Spinner (завантажувача)
Щоб користувач під час очікування відповіді бачив процес завантаження замість порожнього екрана, було створено спінер:
- У файлі `index.html` додано розмітку для блоку `.loader-container` зі спінером та текстом "Завантаження товарів...".
- У файлі `style.css` створено стилі для анімації обертання кола через `@keyframes spin`.
- Реалізовано службовий клас `.hidden` (`display: none !important`), який дозволяє ховати елементи зі сторінки.

### 4. Управління станом інтерфейсу (UI)
У функції `initShop()` налаштовано логіку зміни станів сторінки:
- Перед початком запиту спінер стає видимим (видаляється клас `hidden`), а контейнер товарів очищається.
- Програма очікує завершення завантаження через `await fetchProducts()`.
- Після успішного отримання даних спінер приховується (додається клас `hidden`), а масив товарів перетворюється на картки й виводиться на сторінку.

### 5. Обробка можливих помилок через try...catch
Отримання даних огорнуто в блок `try...catch` для коректної обробки збоїв:
- Якщо запит виконався успішно, відображається список товарів.
- Якщо виникає помилка (наприклад, стан `reject` у промісі), керування переходить у блок `catch`. Спінер приховується, а користувач бачить зрозуміле текстове повідомлення про помилку замість завислого інтерфейсу.
